# План улучшения studio

Статус: черновик, ждёт утверждения владельца. Исходная версия плагина: 3.5.7.

## Цель

1. Сократить правила до тех, что реально меняют поведение современных моделей.
2. Упростить хуки: меньше ложных остановок, меньше кода на сопровождение.
3. Добавить в Claude Code оркестрацию: сильная модель ведёт сессию, отдельные агенты
   делают ревью, поиск и хорошо описанные задачи.
4. Каждое изменение подтверждать замером, а не впечатлением.

## Границы

- Оркестрация только для Claude Code. Поведение Codex и Antigravity не меняется, кроме
  общих правок `AGENTS.md` и хуков.
- Скиллы `idea` и `docs` и SessionStart-хук не меняются.
- Правило из памяти проекта остаётся в силе: правка для одного инструмента не должна
  ухудшать работу другого и идёт через собственный канал этого инструмента.

## Выпуски

Решено владельцем 2026-11-14: все этапы выполняются подряд в одной ветке и выходят одним
выпуском 3.6.0. Проверка идёт без участия владельца: после каждой группы правок агент сам
прогоняет тесты и eval. От владельца нужно одно действие в конце: подтвердить хуки в Codex
через `/hooks` и перезапустить Antigravity.

## Как ведётся работа

- Ветка `improve-studio` от `master`. Каждый проверенный пункт — отдельный коммит.
  Слияние в `master` и push — только с разрешения владельца, один раз в конце.
- Этапы идут подряд без остановок на отчёт. Агент останавливается, только если eval
  показал ухудшение, которое не удаётся снять возвратом правила, или нужно решение
  владельца.
- В конце один отчёт: что изменилось, результаты eval рядом с базовой линией, что не
  удалось проверить, и список действий владельца в Codex и Antigravity.

## Риски

| Риск | Что делаем |
|---|---|
| Eval на учебных проектах не отражает большие проекты | Повтор трёх задач Lira-Sapr-MCP (1.5–1.7) и сверка с реальными журналами (3.10, 4.1, 4.8) |
| Повтор стоит много токенов | Три состояния плагина, а не каждая правка; оценка расхода после первого прогона (1.7) |
| Один прогон на задачу даёт шум | Выводы делаются только по расхождениям, которые повторяются на всех трёх задачах |
| Удалённое правило оказалось рабочим | Правки идут группами с прогоном eval; ухудшение возвращает правило |
| Ослабление guard пропустит запись вне проекта | Владелец принимает это явно до этапа 4; описано в README |
| Общая правка ухудшит Codex | После выпуска читается первый обычный рабочий журнал GringoPO |
| Проблема проявится только на реальном проекте | Каждая группа правок — отдельный коммит, поэтому её можно откатить точечно |
| Worker увеличит число доработок | Выходит в режиме «по усмотрению»; сравнение 5.3 на eval |
| Формат `claude plugin eval` не подойдёт | Запасной вариант: свой запуск через `claude -p` с проверкой результата скриптом |
